Storagefile — микросервис хранения файлов

- v1
    - метаданные: хранение в Postgresql(FileInfoEntity)
    - файлы: хранение в Postgresql(FileBodyEntity)
- v2
    - метаданные: хранение в Postgresql(FileMetadataEntity)
    - файлы: хранение в minIO(docker-контейнер)

## Архитектура
описаны только нюансы

-  ### модуль Core
    - 2 реализации (v1 и v2)
        - при реализации v1 сохранение метаданных и файла было в одной транзакции,  
          из-за того что в реализации v2 метаданные и файлы находятся в разных системах,  
          в методе сохранения(StorageFileManagerMinio - addFile) сначала сохраняем файл в minIO и  
          потом уже сохраняем метаданные, если файл сохранился в minIO но не сохранились метаданные,  
          то предусмотрена Job (CleaningMinIo)
-  ### модуль Adapter
    - реализован на java 8 для работы на микросервисах, использующих java 8
-  ### модуль Job
    - CleaningMinIo - раз в день очищаем minIO от файлов, у которых нет метаданных(особенность реализации метода сохранения)
    - MigrateFilesInMinIo - миграция файлов из v1 в v2.
        - миграция метаданных происходит при первом запуске микросервиса, sql запросом, который запускается с помощью FlyWay
        - миграция файлов уже происходит в MigrateFilesInMinIo

## UI
- помимо UI, которые реализован в модуле Web, у minIO есть свой UI, доступный на порту 9000

## Запуск

- при первом запуске произойдет миграция метаданных из v1 в v2!!!(sql команда, выполняемая с помощью FlyWay)
- также при первом запуске будет создан bucket с определенным именем в minIO, если minIO не подключен, то будет ошибки и микросервис не запустится!!!(смотри StorageFileCoreConfiguration)
- данные расположения minIO нужно указать в storagefile.properties
- настройки для запуска minIO описаны в docker-compose.yml

- запуск docker compose
```bash
    docker compose up -d
```
- остановка docker compose
```bash
    docker compose down
```

- где minIO хранит файли в своем формате
    - это необходимо прописать в volumes: в docker compose(на данный момент там местоположение, это корень проекта(./minio-data:/data) в папке minio-data)

## Дальнейшие улучшений
- на данные момент файл при сохранении и отправке полностью загружается в микросервис(byte[])
  что может быть опасно, если файл будет большой.
    - решение: отдавать не объект с byte[] а InputStream
- реализовать получение файла напрямую из minIO, а не через микросервис(presigned URL)
- Job (CleaningMinIo) - можно сделать обработку не всех данных сразу, а пакетами. (актуально если файлов станет очень много)
- Job (MigrateFilesInMinIo) - подумать о, обработке метаданных со статусом Failed(сейчас просто пытаемся по новой получить файл из v1 и загрузить его в v2)
